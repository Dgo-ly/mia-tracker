# Порядок обновления

## Файлы и доступ

`data.enc` читает действующий сайт: PBKDF2 SHA-256, AES-GCM 256, свежие соль
и nonce при каждой записи. Не сжимать этот файл: браузер ожидает JSON.
`source-state.enc` — зашифрованное внутреннее состояние источников для
сравнения значений, цветов и галочек. Оно сжато перед шифрованием и читается
`scripts/tracker.py`, а не интерфейсом сайта.

Пароль передавать только в память процесса через `MIA_TRACKER_PASSWORD`
или интерактивный ввод. Не записывать его в код, документацию, описание
задания, сообщения коммитов, тесты или журналы. Все открытые данные
размещать вне репозитория с ограниченными правами.

## Один ежедневный запуск

1. Прочитать HEAD основной ветки и сохранить SHA. Из этой версии получить
   код, `data.enc`, `source-state.enc`. Расшифровать локально, проверить
   данные валидатором. Без новых исходников 1С сохранять учётную базу и дату.
2. Получить актуальные метаданные всех шести источников, затем полные
   ограниченные диапазоны с effective values, цветами и checkbox data.
   Скачать оригинальный Office XLSX Василеостровского. Таблицы не менять.
   Точные инструкции приведены в `SOURCES.md`.
3. Нормализовать источники, сравнить с предыдущим состоянием и обработать
   ранее отложенные записи. Служебная дата и перемещение строки сами по
   себе не означают изменение комментария.
4. Для изменённых строк проверить контрагента и клинику. Сохранить файл,
   вкладку, ячейку, время чтения и основание статуса. Не использовать
   нечёткое совпадение названий как единственное основание объединения.
   Дубли и сокращённые имена требуют явной проверки.
5. Сформировать проверенный JSON патча. При неизменных доказательствах
   сохранять текущий статус. Пустая свежая ячейка не доказывает, что старый
   комментарий нужно удалить: переносить его с указанием прошлого среза.
6. Для сравнения дня взять последний сопоставимый снимок предыдущего дня,
   для недели — снимок на дату семь дней назад из Git. Правдиво указывать
   фактическую дату базы. Старые XLSX до перехода на 1С имеют другую
   денежную основу и не заменяют снимки сайта.
7. Подготовить кандидат. Проверить неизменность `p`, `d`, `dv`, состава
   строк, распределения городов, дат 1С, сохранённых счётчиков; проверить
   суммы по статусам и соответствие блока сверки основным строкам.
8. Зашифровать кандидат и состояние источников. Внутри состояния сохранить
   хеш опубликованного JSON, журнал обработанных изменений и список
   `pending_changes` с неразрешёнными случаями.
9. Повторно прочитать HEAD. Если он изменился, перечитать данные и
   подготовить кандидат на их основе. Не применять force push.
10. Опубликовать оба зашифрованных файла одним коммитом. При обновлении ref
    использовать `expected_sha`. Не включать открытые данные в коммит.
11. Проверить SHA файлов в коммите и доступность новой версии на GitHub
    Pages, расшифровать полученный файл локально и подтвердить дату.
    Сообщить результат и отложенные случаи.

Если все источники прочитаны и изменений нет, это успешная проверка.
Если сегодня уже опубликована проверенная версия с тем же состоянием,
новый коммит не нужен. Не менять дату проверки при недоступном источнике.

## Команды и патч

`scripts/director_sources.py` нормализует снимки. `scripts/status_rules.py`
содержит правила, `scripts/validate_data.py` проверяет структуру и суммы.
`scripts/tracker.py` применяет проверенные патчи, строит сравнения и шифрует.

Патч содержит `baseline_sha256` (канонический хеш всего исходного JSON),
`source_checked_at` (ISO timestamp), `source_count`, `status_rules`, `updates`.
Элемент `updates`: `clinic`, точное `name`, `before`, `set`, `source`, `reason`.
Разрешённые поля `set`: `c`, `s`, `src`, `edo`, `dep`, `tabs`, `x`.

```bash
python scripts/tracker.py prepare \
  --baseline ../private-run/baseline.json \
  --patches ../private-run/patches.json \
  --week ../private-run/week.json \
  --output ../private-run/candidate.json
python scripts/tracker.py validate ../private-run/candidate.json
python scripts/tracker.py encrypt ../private-run/candidate.json data.enc
python scripts/tracker.py encrypt ../private-run/source-state.json source-state.enc --compress-state
python -m unittest discover -s tests
```

Нельзя удалять строки, ставить нули или отключать проверки ради прохождения
валидации. Новые суммы директора, новый срез, контрагент или структура листа
требуют отдельной сверки и не проходят обычным патчем комментария. Сохранять
такие случаи в `pending_changes`, объяснять причину пользователю. Остальные
проверенные изменения можно опубликовать с явным указанием неполноты.

## Правила статусов

Учётный остаток, статус работы и наличие комментария — разные показатели.
«Отправлено» не означает приём бухгалтерией; «возврат» не означает получение
денег. Прежняя категория «закрыто по статусам» включает авансы и другие
состояния и не равна погашению бухгалтерского остатка.

Отрицательные ключевые слова имеют приоритет над устареванием комментария,
а устаревание — над обычными положительными и рабочими ключами. Проверка
роста требует сопоставимых денежных срезов. Сумма 1С не сравнивается с
предыдущей суммой директора. Статусы ЭДО/цветов требуют фактов источника.

`explicit_missing_documents=True` — точечное расширение старых правил:
весь комментарий должен состоять из нумерованных документов с отметкой
«не нашла / не нашёл / не нашли», тогда статус — «Проблема». Оговорки «только»,
позднейшее исправление и дополнительный текст не подходят. Расширение не
изменило ни одной из 663 проверяемых текстовых исторических классификаций.
Оно применяется к новым доказательствам, без массовой смены старых статусов.

## Новый месяц 1С

Нужны исходные `.xlsx`/`.xls`. Организация и дата берутся из самого отчёта.
Проверять группы и итоги; одинаковые файлы определять по хешу. Москва и
Краснодар «Стоматолог Л.А.» относятся к одному юрлицу: одинаковые отчёты
нельзя суммировать. Городское распределение подтверждается отдельно.

`dir_total` и `total_dir` складывают положительные `dv`; отрицательные
остатки их не уменьшают. Директорский заголовок не заменяет сумму строк.
Группы «Поставщики», «Прочее», «Покупатели» проверяются отдельно.

Восстановленная из сайта база сохраняет прежние суммы, но не заменяет
оригинальные отчёты и не доказывает первоначальную группировку.
Полный импорт нового месяца не реализован ежедневной командой `prepare`.

## Расписание и одновременные обновления

Желаемое время — 19:00 Europe/Moscow. Задача ChatGPT должна иметь доступ
к подключённым Drive и GitHub. Здесь нет самостоятельного фонового сервера.
Пароль уже передан пользователем в исходной беседе; он не включается в
публичный код или текст задания. При отсутствии доступа к нему нельзя
подбирать пароль или публиковать непроверенные данные.

В истории есть обновления прежнего процесса Claude. Из этого репозитория
нельзя выключить внешнюю задачу Claude. При её продолжающейся работе
обязательна проверка HEAD; о конкурирующем обновлении сообщать пользователю.
Для окончательного переключения прежняя задача отключается в том сервисе,
где она создана.

## Откат

Вернуть оба зашифрованных файла из последнего проверенного коммита новым
коммитом с защитой HEAD. Не переписывать историю и не менять пароль.
Проверить опубликованные байты и дату так же, как после обновления.

## Ежедневное чтение из Google Drive

Команда ниже проверяет все шесть источников и создаёт зашифрованный отчёт.
Она получает идентификаторы таблиц из опубликованного `source-state.enc`.
Для запуска нужны включённые Drive API и Sheets API, а также учётная запись
с правом чтения всех шести файлов. Программа использует Google Application
Default Credentials. На автоматическом запуске передавайте
`MIA_TRACKER_PASSWORD` из хранилища секретов в окружение процесса.

```bash
python -m pip install -r requirements.txt
python scripts/check_sources.py --state source-state.enc --output ../private-run/review.enc
```

Планировщик может запускать команду ежедневно в 19:00 по Москве после
получения актуальной основной ветки. Если чтение оборвалось, выход
с ненулевым кодом означает, что нового подтверждённого отчёта нет.
Файл отчёта содержит текущий снимок, различия и прежние отложенные случаи.
При изменениях используйте шаги проверки и подготовки патча из этого
руководства. Сама команда ничего не публикует.
