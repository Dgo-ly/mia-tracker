# Источники директорских комментариев

Этот документ описывает получение исходных данных для обновления трекера. Исходные таблицы читаются без изменений. Бухгалтерские суммы берутся из отдельно проверенной базы 1С. Директорские суммы нужны для сравнения и сами по себе не заменяют бухгалтерскую базу.

## Состав источников

Идентификаторы файлов берутся из зашифрованного состояния источников.

| Ключ | Источник | Формат |
| --- | --- | --- |
| `ami` | АМИ Клиник Север | Google Sheets |
| `krd` | Стоматолог Л.А., Краснодар и совместные записи | Google Sheets |
| `msk` | Стоматолог Л.А., Москва | Google Sheets |
| `loft` | Лофтдент | Google Sheets |
| `vas` | МИА Василеостровский | XLSX на Google Drive |
| `lig` | МИА Лиговский | Google Sheets |

## Получение снимков

Использовать доступ пользователя к Google Drive. Нельзя подменять недоступный источник старым снимком и при этом сообщать об успешном полном обновлении.

1. Для каждого файла прочитать `get_file_metadata` с полями `id,name,mimeType,modifiedTime,webViewLink,size`. Сохранить `structuredContent` без изменения имён полей.
2. Для пяти нативных таблиц вызвать `get_spreadsheet_metadata` с `include_conditional_format_rules=true`. Записать точные названия вкладок, `sheetId`, видимость и размеры. Не применять этот метод к XLSX Василеостровского.
3. Прочитать небольшие диапазоны заголовков на подтверждённых вкладках. Затем через `get_spreadsheet_range` найти конец данных в столбцах имён: обычно A, для московского `Лист1` — B; у московского `Лист2` также проверить F. Для списка УПД КРД проверить A и E: строки документов могут иметь пустое имя поставщика и продолжаться после последнего заголовка группы. Ограничивать диапазоны реальными размерами вкладок.
4. Через `get_spreadsheet_cells` прочитать полные ограниченные диапазоны до последней содержательной строки. Передавать один A1-диапазон на вкладку, заключая её точное название в одинарные кавычки. Сохранить `structuredContent` в `{key}_cells.json`.
5. Для Василеостровского после проверки MIME вызвать `fetch` с `download_raw_file=true`, `include_base64=false`. Скачать оригинальный файл через возвращённый `file_uri` в `vas.xlsx`. Не использовать текстовый предпросмотр вместо XLSX: нужны все строки и цвета.
6. Повторно проверить метаданные после чтения. Если `modified_time` изменилось во время получения данных, перечитать затронутый источник, чтобы снимок не смешивал разные версии.

Нужная маска CellData:

```text
formattedValue,effectiveValue,userEnteredValue,effectiveFormat(backgroundColor,textFormat(bold,strikethrough,foregroundColor)),dataValidation(condition),note
```

`effectiveValue` сохраняет числа и логические значения. `formattedValue` сохраняет показанные даты в комментариях. Чекбокс FALSE нельзя считать пустой ячейкой. Цвета читаются из `effectiveFormat`, чтобы учитывать итоговое оформление.

Имена доступных инструментов могут иметь префикс приложения; например, `mcp__codex_apps__google_drive_get_spreadsheet_cells`. Перед вызовом использовать текущую схему инструмента. В инструменте чтения простых значений `sheet_name` и `range` передаются отдельно; в CellData используется полный A1-диапазон с названием вкладки.

### Формат каталога входных данных

```text
metadata.json
ami_cells.json
krd_cells.json
msk_cells.json
loft_cells.json
lig_cells.json
vas.xlsx
```

Структура `metadata.json`:

```json
{
  "ami": {
    "file": "structuredContent результата get_file_metadata",
    "sheets": "structuredContent результата get_spreadsheet_metadata"
  },
  "vas": {
    "file": "structuredContent результата get_file_metadata"
  }
}
```

В реальном JSON вместо поясняющих строк должны находиться полные объекты результатов. Аналогичные записи нужны для всех шести ключей. В этих файлах нет токенов доступа или временных ссылок для скачивания.

## Обрабатываемые вкладки и столбцы

Текущий набор зафиксирован в `ACTIVE_TABS` парсера. Появление новой вкладки, смена заголовков или столбцов требует проверки правила выбора периода перед публикацией. Не выбирать самый новый лист только по его позиции.

| Источник | Активные вкладки | Полезные столбцы |
| --- | --- | --- |
| АМИ | `на 01.10.2026` | A:I: поставщик, сумма, отдел, ЭДО, статус, комментарий, ответственный, заметки, флаг переплаты |
| КРД | `1.09 (КРД и МСК)`, `КРД 01.09.26 (+одинаковые с МСК)`, `30.09. КРД МСК ` | A:G для первых двух; A:H для сверки |
| КРД, УПД | `Необходимо подписать в эдо КРД` | A:J: группы поставщиков, платежи, документы, флаг подписи |
| Москва | `Лист1`, `Лист2` | A:I и A:H соответственно; второй лист содержит свободные комментарии и вспомогательный список |
| Лофтдент | `Лист1`, `Лист2` | A:E и A:G; во втором листе F — загрузка в бухгалтерию, G — подробности |
| Василеостровский | `Лист2` | Оригинальный XLSX; сумма B, комментарии C:D; числовой остаток C не является текстовым комментарием |
| Лиговский | `Поставщики Ноябрь 2026` | A:E: поставщик/группа, «Мы должны», «Нам должны», ЭДО, комментарий |

Пробел в конце имени вкладки `30.09. КРД МСК ` значим. Вкладка `ОБРАЗЕЦ` не является источником текущих записей.

Для расследования и смены периода можно дополнительно читать предыдущие вкладки. Парсер умеет разбирать ранее использовавшиеся формы, но включает в состояние обновления только явно выбранные активные вкладки. Все метаданные вкладок сохраняются для обнаружения изменений структуры.

## Установленные особенности данных

- У АМИ название текущей вкладки указывает октябрь 2026 года, а её заголовок остался сентябрьским. Сохранено ранее применявшееся определение периода по названию вкладки. Это явное исключение для данного источника.
- Вкладка КРД `1.10` содержит в заголовке 2025 год. Она не используется как более свежий срез без дополнительной проверки.
- КРД содержит отдельные, совместные и московские записи. Нормализатор сохраняет исходный филиал. Он не распределяет сумму между подразделениями и не суммирует одноимённые строки разных вкладок.
- Один поставщик может иметь несколько строк комментариев. Они сохраняются отдельно с исходными координатами. Изменившаяся группа с повторяющимися поставщиками требует проверки.
- Один УПД может встречаться в нескольких платёжных строках. Идентификатор включает поставщика, номер и дату УПД, дату/сумму/назначение платежа и тип документа. Нельзя считать каждую платёжную строку отдельным УПД или повторно суммировать его полную сумму.
- В таблице Лиговского есть группы «Поставщики», «Прочее» и «Покупатели». Их принадлежность сохраняется. Существующая бухгалтерская база и директорские группировки могут различаться; нормализатор не меняет финансовый охват.
- В старом сайте `dv` некоторых записей означает отрицательный директорский долг. Для контроля общего оплаченного остатка используется сумма положительных `dv`; простая сумма подписанных значений даёт другой показатель.
- Числовые остатки и денежные значения в колонке заметок не превращаются в текстовые комментарии. Числа Excel, отображаемые датами, сохраняются как показанные даты.

## Нормализация и сравнение

Для чтения XLSX требуется `openpyxl`; остальные операции используют стандартную библиотеку Python. Скрипт ничего не скачивает самостоятельно.

```bash
python3 scripts/director_sources.py \
  --input-dir "$MIA_TRACKER_INPUTS" \
  --metadata metadata.json \
  --output "$MIA_TRACKER_PRIVATE_OUTPUT/source-state.json"
```

Сравнение с предыдущим расшифрованным состоянием:

```bash
python3 scripts/director_sources.py \
  --input-dir "$MIA_TRACKER_INPUTS" \
  --output "$MIA_TRACKER_PRIVATE_OUTPUT/source-state.json" \
  --previous "$MIA_TRACKER_PRIVATE_OUTPUT/previous-source-state.json" \
  --changes-output "$MIA_TRACKER_PRIVATE_OUTPUT/source-changes.json"
```

Публичный API модуля:

```python
state = normalize(source_dir, metadata_filename="metadata.json")
changes = compare_states(previous, state)
```

`source_state` содержит `schema_version`, время получения и шесть источников. Для каждого сохраняются метаданные, выбранные вкладки, исходные координаты, нормализованные записи, `content_sha256`, структура и её хеш. Хеш содержимого считается по активным вкладкам; время получения в него не входит.

Сравнение возвращает добавленные, изменённые и удалённые группы по источнику, вкладке и поставщику; для документов дополнительно учитывается УПД. Изменение только номера строки не считается изменением содержания. Перестановка строк не удаляет историю.

Отсутствующий источник или активная вкладка, чужой идентификатор файла, неразбираемая сумма и повторный идентификатор физической записи вызывают ошибку. Добавление/удаление групп, изменение структуры, суммы или подразделения и изменение группы с повторяющимися поставщиками получают `requires_review=true`. Наличие отметки проверки означает, что автоматическая публикация должна быть остановлена до разбора причины.

Сравнение не назначает статусы и не изменяет сайт. Применение подтверждённых полей, расчёт итогов, проверка неизменности бухгалтерской базы, шифрование и публикация выполняются отдельным этапом.

## Хранение

Каталог входных данных, состояния и результаты сравнения содержат конфиденциальные сведения. Их размещают в приватном рабочем каталоге вне репозитория. В публичный GitHub допускаются код, инструкции и зашифрованные файлы. Пароль, открытые выгрузки, списки контрагентов и временные ссылки для скачивания в репозиторий не записываются.
